# 审查报告 6 · 字幕工坊 Subtitle Studio v0.4.0（浏览器 → 原生桌面重构轮）

- 审查时间：2026-10-17
- 审查方式：四视角子智能体并行（架构与分层 / 正确性与边界 / 线程与资源 / 交互与打包，只读不改）+ 主智能体逐条回读源码核实 → 当场修复 → 回归测试
- 本轮主题：把「打开浏览器」重构为 PySide6 原生桌面窗口（Qt Widgets + QtMultimedia，无浏览器内核），后端抽出共用业务层
- 结论：**严重 0 + 关键 6 项（已修复）+ 建议 15 项（全部修复）+ 遗留 5 项（记录不修）**
- 说明：四视角中子智能体**两次执行失败**（`model finished without a visible final answer`）：架构、线程与资源、交互与打包三视角成功；正确性与边界视角两次未产出，改由主智能体逐项人工核读（见第三节），并补测试守卫。

---

## 一、本轮改动

- **新增 `desktop/` 界面包**（11 个模块）：`app`（QApplication 入口 + 异常兜底）、`logging_setup`（日志落盘 + 接管窗口程序里为 `None` 的 `stdout`/`stderr`）、`theme`（配色与 QSS）、`cues`（字幕模型与编辑操作，纯 Python）、`bridge`（后端桥接 + 后台识别线程）、`player`（QtMultimedia 播放器 + 独立透明字幕叠加窗口）、`timeline`（自绘时间轴）、`cue_table`（字幕列表）、`dialogs`（识别/平移/帮助 + Toast）、`main_window`（装配与编排）、`__init__`（延迟导入）
- **新增 `backend/service.py`**：导出序列化（含 ASS BOM）、导入解析、媒体落位 `MediaStager`、体积上限、任务编排（`run_transcription` / `create_import_job`），HTTP 路由与桌面界面共用
- **`app.py` 双模式入口**：默认桌面窗口（不启动 HTTP）；`--server-only` / `SUBTITLE_STUDIO_NO_GUI=1` 启动 uvicorn 服务
- **`subtitle_studio.spec`**：`console=False`、收集 PySide6(Core/Gui/Widgets/Multimedia)、排除含内置 Chromium 的 QtWebEngine 等 40 个 Qt 模块
- **测试/文档**：新增 4 个测试文件（conftest + 桌面模型/桥接/控件）；README 与 `docs/版本说明.md` 同步

## 三、正确性与边界视角（人工核读替代）

子智能体两次未产出结论，改由主智能体逐项核读，结论如下（每项均有单测守卫）：

| 核对点 | 结论 |
| --- | --- |
| 越界索引 / 空列表（`remove`、`split_at`、`set_start/end`、`merge_next`、`_on_row_selected`） | 全部有 `0 <= index < len` 守卫；`CueListPanel.rebuild()` 会把越界的选中索引回退为最后一条、播放中索引清空 |
| 时间边界（NaN/Infinity/负值/零长） | `CueList._normalize` 跳过非法项并按 `backend.srt.round3` 归一；`_apply_shift`、`move_to`、`resize_*` 均保证正时长 |
| `clamp` 低>高反例 | `set_start_at`、`resize_start` 已加 `max(0.0, ...)`；`split_all_by_punct` 的 `clamp(cursor, start, max(start, end-0.1))` 与前端同序，不产生负时长 |
| 时间轴拖动阈值与排序不变量 | 5px 阈值、边缘把手（>16px 才出现）、拖动结束 `sort()`、`cancel_drag` 照常提交，均有测试 |
| 与前端语义等价（add/merge/split/punctSplit/shift/overlaps/阈值 0.001/时间格式） | 逐函数比对一致；`round3` 复用后端实现，无 1ms 偏差（本轮唯一主动差异「未提交编辑」已按第 6 项修复） |
| 导出/导入边界（空字幕、UTF-8/GBK 回退、超限、ASS BOM、文件名扩展名替换） | 均复用 `service` 单一实现并有测试；界面层另有「空字幕禁止导出」拦截 |
| `MediaStager` 异常清理 | `__exit__` 在异常路径调用 `abort()` 删除半截文件；`write` 与 `copy_from` 双重体积校验 |

## 四、误报澄清

- 「spec 可能漏收集 Qt 多媒体插件 / platforms 插件」：回读构建产物的 `build/subtitle_studio/Analysis-00.toc` 确认 `PySide6\plugins\multimedia\ffmpegmediaplugin.dll` 与 `windowsmediaplugin.dll` 均已打包；`QT_EXCLUDES` 不含 `multimedia`，PyInstaller 的 PySide6 hook 负责收集插件 → 非问题。
- 「`_threads` 注册与 `thread.start()` 之间存在 `busy` 误报窗口」：窗口为纳秒级且 `delete_job` 当前无界面入口（桌面版未暴露删除任务），影响可忽略 → 记录为遗留 L3 而非缺陷。
- 「`RotatingFileHandler` 多线程滚动可能触发 Windows 文件占用错误」：`logging.Handler.handle()` 自带锁，滚动在锁内完成，`logging.raiseExceptions` 会吞掉写失败 → 保留为遗留 L4（极端并发下可能丢一条）。

## 六、遗留（记录不修）

| # | 问题 | 原因 |
| --- | --- | --- |
| L1 | `PySide6` 为硬依赖：服务模式部署（不需要界面）也会装 Qt | 桌面是主形态，拆 extras 会让 `pip install -r requirements.txt` 的默认路径缺界面；README 已说明服务模式用法 |
| L2 | 保存仍在 GUI 线程落盘（`JobManager.set_segments` 含文件 IO，持锁） | 防抖 1.2 秒 + 单次写入毫秒级，字幕量极大时才有可感知卡顿；改为线程池需重新设计保存顺序 |
| L3 | `_threads` 注册/`start()` 与 `busy` 判断存在理论竞态窗口 | 纳秒级、无界面入口依赖该判断；逻辑上「先注册再启动」已是安全侧 |
| L4 | 极端并发下日志滚动可能丢一条 | `logging` 内部锁 + `raiseExceptions` 已兜底，概率极低 |
| L5 | 桌面与浏览器两套界面需同步维护 | 浏览器界面保留给服务模式/调试；一致性由 `test_consistency.py`（标点集）与 `tests/test_desktop_*`（编辑语义）守卫 |

## 七、结论

修复 21 项（0 严重 + 6 关键 + 15 建议），遗留 5 项均为低风险记录项；207 项测试全过、真实窗口与打包 exe 均完成冒烟。**可以发布 v0.4.0。**
